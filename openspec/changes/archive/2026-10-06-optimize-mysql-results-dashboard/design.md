# Design

## Context

动机见 `proposal.md`。项目采用静态 HTML/CSS/JavaScript，`site/app.js` 中同时包含取数、页面渲染与手写 SVG 折线图；不存在前端框架或站点单元测试。

现状检查：

- `site/mysql.html` 依次堆叠资源卡片、实验范围、QPS、TPS、混合 p95/p99 图、读写比值卡片、稳定性表和原始结果。
- 图表固定 `900 × 340` viewBox，移动端强制最小宽度 680px；只能依赖鼠标悬停 SVG title 查看数值。
- QPS 当前为线性轴，TPS 和延迟为对数轴。延迟图同时显示六条线，图例只使用相同颜色，缺少与线型对应的视觉标识。
- 环境区仅显示版本、平台、合并资源值和时间；`site/data/mysql.json` 已记录 MySQL 参数、压测端限额、Docker/Compose、VM 资源和宿主机信息。
- 运行时目前以 `|` 分隔字符串记录，展示层需要有校验的适配与缺失回退。
- `add-mysql-benchmark-mvp` 的 27 项任务已完成，但尚未归档，主规格目录为空。本 change 独立补充界面契约，不覆盖测试或统计契约。

## Goals / Non-Goals

**Goals:**

- 以已有结果生成紧凑看板，降低比较读、写和混合场景所需的滚动与操作。
- MySQL 容器资源上限始终显著可见，展开后能检查完整环境与协议。
- 坐标轴、单位、数值提示、场景筛选和移动端阅读形成一致的交互。
- 不改变统计结果与测试来源，建立覆盖展示逻辑和浏览器交互的回归测试。

**Non-Goals:**

- 不重新压测，不修改 Docker 配额、MySQL 配置、sysbench、聚合算法或结果 JSON。
- 不新增实时资源监控、CPU/I/O 使用率或历史运行批次比较。
- 不迁移前端框架，不增加后端、不发布到公网。
- 不修改旧 change，不自动归档。

## Decisions

### 1. 报告式布局与四面板看板

建议页面结构：

```text
紧凑导航：Performance Profile / MySQL / 返回索引
MySQL 8.4.11 · 本地 Docker · 测试时间
资源摘要：CPU 上限 4 | 内存上限 6 GiB | Buffer Pool 3 GiB | ARM64
实验摘要：10 表 / 100 万行 / 60s 预热 / 120s 测量 / 2-3 次

性能看板：共享场景筛选、并发选择 1 / 8 / 32
  QPS 图                    TPS 图
  p95 图                    p99 图
同并发数值：场景 / QPS / TPS / p95 / p99 / 每事件查询数 / 稳定性

结果明细：9 个组合 + 可展开的逐次结果与原始输出
环境明细：MySQL / 压测端 / Docker VM / 宿主机 / 协议
边界说明：本地虚拟化环境 / 指标来源
```

桌面为两列指标面板，移动端为单列。标题使用报告级字体而非 hero 字体，一级导航、资源摘要与图表之间不设置大面积留白。页面区段保持未加框的常规布局，仅图表工具和重复组件允许使用不超过 8px 圆角的边框。

替代方案是保留三张大图及比值卡片，但仍存在用户指出的冗余和图表量级/线型辨认问题。直接使用四个面板可以分离单位，并在同屏比较。

### 2. 通过图表与同并发数值直接比较

删除 `comparison-grid` 和相关渲染，现有 `comparisons` 字段保留在数据文件中以维持兼容，但本次界面不展示比值卡片或专门比值表。

场景采用复用的蓝、橙、绿配色与中文短名称，所有面板顺序一致。使用共享复选框控制场景可见性；并发采用分段选择器，默认选择当前报告中最高的已记录并发（现有为 32），在四图突出该列，并在下方列出同并发指标。图内鼠标/触摸选择同样更新共享并发；键盘可通过分段控件访问同等信息。

替代方案是要求用户逐图悬停并记住数值，不利于触屏和跨指标对照。当前数据只有三档并发，不引入自由缩放或复杂钻取。

### 3. 默认对数轴，保留逐面板线性切换

此次优化建议四图默认使用对数 Y 轴，以便同屏区分低于 1ms 的读延迟与数十毫秒的写延迟，以及吞吐的多数量级跨度。每个面板均有“线性 / 对数”分段控件，当前刻度作为轴元数据展示。此默认是本提案的设计选择，取代现有 QPS 线性默认；测试数值不变。

- 吞吐用 QPS/TPS，刻度适度使用 `K`/`M` 紧凑单位，提示和结果表提供完整数值。
- 延迟统一采用 ms，采用能保留小数有效位的格式，`0.027 ms` 不被舍入为 `0`。
- 对数刻度优先选取 1/2/5 倍十进位的整洁刻度，并按面板高度约束标签数量，避免 135K 顶部留出到 1M 的大面积空间。
- X 轴采用已测试并发的类别轴，明确显示 1、8、32，不插值成未经测试的点。
- 零值只在线性轴绘制；对数轴显示不可绘制状态。缺失、负值及非有限值不钳制为下限，不连接缺失点两侧曲线。
- 场景颜色不因筛选改变；四图中选中点和数值区共同体现状态，不仅依赖颜色。

保留线性轴作为观察绝对差距的替代，避免对数视觉弱化幅度被理解为实际差距更小。

### 4. 沿用静态实现，拆出可测试的展示辅助模块

继续使用现有 HTML、CSS 和 SVG，不增加前端框架、远程 CDN 或图表运行时依赖。把数值格式化、环境适配、轴刻度/映射和面板数据投影集中到 `site/` 内可由浏览器与 Node 测试共享的小模块中。`site/app.js` 保持为加载与 DOM 交互入口。

与引入完整图表库相比，当前只有四个面板、三种场景、三档并发；沿用静态实现可以限制此次变更范围。测试覆盖正值对数映射、缺失数据断点和交互；未来若需要时间序列与缩放，再单独讨论工具选择。

### 5. 环境字段分组与来源映射

只读 `site/data/mysql.json` 内的报告快照，不读取 `.env`、Compose 当前配置或现场 Docker 状态来补历史值。

| 分组 | 显示项 | 当前数据来源 |
| --- | --- | --- |
| MySQL 容器资源 | CPU 上限、内存上限、平台 | `environment.container.mysqlCpuLimit/mysqlMemoryLimit/platform` |
| MySQL 配置 | Buffer Pool、连接上限、隔离、提交刷盘和 binlog 同步参数 | `environment.mysql.*` |
| 版本与来源 | MySQL 版本、镜像引用与完整摘要 | `environment.mysql.version`、`environment.container.mysqlImage/repositoryDigests` |
| 压测端 | CPU 上限、内存上限、sysbench 版本、镜像 | `environment.container.loadGenerator*`、`environment.loadGenerator.*` |
| Docker VM | Docker/Compose 版本、运行时、内核、可见 CPU/内存、存储驱动 | `environment.runtime.*` |
| 宿主机 | 型号、架构、逻辑 CPU、物理内存 | `environment.host.*` |
| 实验协议 | 表数/行数、并发、预热/测量、重复规则 | `dataset.*`、`protocol.*` |
| 实际结果 | 测试时间、每组合次数与稳定性 | `component.testedAt`、`stability.*` |

Docker 内存字符串 `6g`/`1g` 按二进制量显示为 6 GiB/1 GiB；Buffer Pool 原始字节值显示为 3 GiB。CPU 标为配额上限，不称为四个独占物理核；VM 与宿主机资源不得合并到容器资源行。字段缺失显示“未记录”，不把 `sync_binlog=1` 解释为 binlog 已开启。

目前 `dockerInfo` 的格式为 `运行时|内核|CPU|内存字节|存储驱动`，`dockerServer` 为 `版本|平台`。适配层只接受匹配字段数及类型的输入；解析失败保留原始记录，并将无法可靠识别的明细标记为未记录。不改变现有结果 schema。

摘要中的 MySQL 配额、内存和 Buffer Pool默认展开，其他明细使用原生折叠区。长 digest 允许换行并保留完整值。时间显式采用 Asia/Shanghai（UTC+8），测试时间不使用重新生成报告的时间替代。

### 6. 结果质量与状态处理

看板直接展示 `series.points` 的已汇总指标，不重算平均值/中位数，也不隐藏不稳定组合。数值区与逐次明细均带稳定性文字标记；“不稳定”不会被当作失败或改为成功。

在环境/协议明细保留每事件/事务查询数，说明 `read_write` 每事件包含 20 条查询而点查/索引更新为 1，避免把不同语义的 TPS 当成单条 SQL 延迟。p95 标明为直方图近似，p99 为 sysbench 原生输出，不声称更高精度。

加载阶段显示定尺寸占位，失败显示错误及重试，空图显示数据状态而不是零线。错误状态在页面可见，控制台作为辅助诊断。原始结果链接继续使用现有 `/artifacts/mysql/` 路由，不新增服务能力。

索引页沿用组件入口但缩减留白，将“写读吞吐比”替换为环境/资源信息和带场景、并发及稳定性语义的最高观测值，不能把不稳定观测改称稳定能力上限。

### 7. 响应式与验证

图表宽度随容器变化，使用容器测量或 ResizeObserver 更新画布尺寸、坐标和合理的刻度数量；文本维持稳定像素字号，不靠 viewport font scaling。取消移动端 680px 的 SVG 强制宽度。

详细表格可以在自身横向滚动；图表、环境、图例、控制项和页面整体不能溢出。控制项必须有可访问名称与焦点样式，提示内容在面板边界内且不依赖浏览器原生 title。

单测验证展示辅助逻辑；浏览器验证覆盖 1440 × 900、1024 × 768、390 × 844、375 × 812，并检查缩放、场景筛选、并发选择、刻度切换、原始链接和加载异常。截图必须检查小量级曲线仍可见、长环境文本不重叠。

## Risks / Trade-offs

- [对数轴改变差距的视觉感知] → 明确刻度，保留线性切换和精确数值，不据屏幕距离推导吞吐倍数。
- [现有环境字符串不是稳定结构化对象] → 受检适配、缺失回退与原始信息保留，不改旧数据格式。
- [已有报告包含不稳定组合] → 在图表关联数值和明细中保留状态，不包装为稳定性能上限。
- [新增交互使手写图表复杂] → 限制为当前指标与并发集合，拆出测试辅助逻辑，不实现任意缩放/实时刷新。
- [环境扩充重新拉长页面] → 关键 MySQL 配额默认可见，详细环境与逐次结果可折叠，图表位于明细前。
- [共享 CSS 或错误状态影响索引入口] → 同步设计索引，并纳入双页面浏览器回归。
- [展示变更被误当成重新测试] → 保持测试日期与全部数据文件不变，最终检查数据文件无差异。

## Migration Plan

1. 实施前确认本提案；之后沿用现有结果快照作为 fixture，不启动压测容器。
2. 先完成展示辅助模块及单测，再重组详情页、环境与交互。
3. 同步索引、加载/空/错误状态和原始结果导航。
4. 用现有本地服务检查桌面/移动布局与数据一致性；原有 `npm run site` 入口和 URL 不变。
5. 验证所有结果与压测文件无改动后提交界面及测试。回滚只撤回本 change 的界面相关改动，无数据迁移。
