## Context

见proposal.md。原run.mjs可运行32并发，但正式整组collector固定六场景×1/8/16且必须有缓存实验；通用partial不能正式发布。experiment.mjs的单记录和重复验收可以复用，完整矩阵校验仍需保留。measureRepeats复用既有30%补跑策略。页面并发由真实points和协议取并集，目前选中并发的表格仍为无观测场景输出空值。

## Goals / Non-Goals

**Goals:** 以小型专用入口完成两个32并发正式组合和可复算的增量发布，不改变完整实验默认协议。保持所有旧观测和独立实验，来源和日期可追溯。

**Non-Goals:** 不实现通用增量实验框架，不重新测量1/8/16、缓存或热点，不补其他场景，不新增64并发。尚在讨论的页面开头总结不在此change中。

## Decisions

### 1. 专用入口复用底层能力

增加小型32并发补测入口/验收模块，复用prepare清单前缀、标准脚本参数、measureRepeats、原始解析、startResourceCapture和日志恢复。各场景独立准备原100万行数据，不能沿用热点组已修改的数据。每场景只预热一次，重复次数及汇总保持基础协议。不给run/collect通用partial增加正式发布特权，不把EXPANDED_CONCURRENCY全局改成四档。

沿用已验证的负载结束握手收尾方式，正式输出完成后关闭资源窗口再退出容器，避免正常退出与采样竞态；保留5秒及72/100/10门槛，不忽略活动期采样错误。核验实际容器限额、ARM64镜像、MySQL软件、3 GiB缓存、1/1日志和无并行连接；使用caffeinate防闲置休眠。捕获中断只清理自己创建的准备和负载容器，回读恢复；dry run不能写文件或启动容器。

### 2. 严格验收后最小合并

补测使用独立组、每场景准备清单及原始记录。专用验收严格限制两个场景和32并发，复用validateExperimentRun及validateRepeats并补充原始线程数、实际时长、SQL参数、同批和软件匹配核验。复算所有正式资源、重复统计和稳定性，禁止缺组、重复ID、跨组和恢复未确认发布。

只追加目标series.points、对应stability与rawResults，并保存补测自身协议、日期和环境的元信息；原series级日期和来源不改，新的point及组合记录自身日期与组。基础protocol.concurrency保持1/8/16，页面从真实点获得32档，并在环境明细注明32仅有两个场景。峰值/索引代表值可按实际点重算，不制造旧值变动。保存旧报告于站点之外，临时写入后原子替换；核验旧点、缓存、热点及非目标字段深度不变，写入前检查原报告未被并发修改。

### 3. 支持稀疏但真实的并发矩阵

32并发选中表只列有观测的两个场景，不把另外四场景显示为零或假失败。图表保留其他场景原真实终点，既有筛选与刻度不变；32组合明细使用自身日期/环境/原始资料。峰值日期优先从观测自身读取而不是一律使用series日期。更新浏览器fixture，不让过去对每场景相同点数或固定72个图点的假设污染真实数据验收。

### 4. 规范和过程边界

修改mysql-expanded-formal-results中的矩阵、整组发布和展示要求，原完整入口不变，只添加明确批准的两场景32并发例外；其Purpose在同步时限定为基础实验并提及批准的增量，以避免旧“不混入旧批次”绝对表述与保留基线冲突。结论只能说明本配置下扩展趋势，不能仅凭平台期断言CPU、I/O或MySQL唯一瓶颈。页面不添加跨批次过程横幅，但组合日期真实记录。

## Risks / Trade-offs

- [32与历史16不同时测量] → 按用户要求不复测16，核验相同环境、结构和协议，保留独立日期及重复波动，不伪称同批控制实验。
- [既有collector整体替换会丢独立热点字段] → 使用专用严格增量合并，不调用通用publish，不放宽原完整矩阵校验。
- [新增档位让未测场景看似零值] → 选中表过滤无观测场景，曲线只含真实点，不插值延长。
- [宿主机休眠或资源采样不完整] → 防休眠及严格原始证据验收；无效记录隔离，需改变正式条件或补测无效组合时先说明并获确认。

## Migration Plan

先实施入口、验收/合并及必要页面改动，通过协议、重复、证据和字段隔离单测及稀疏矩阵fixture。必要短验证仅保存在verification，当前报告保持不变。串行执行两组合并验收后原子发布，检查实际桌面/移动截图、所有资料链接及旧观测不变。记录Git提交与验收证据，同步主规范并按用户授权归档change。失败时不发布、不自动扩大测试；不删除数据卷。
