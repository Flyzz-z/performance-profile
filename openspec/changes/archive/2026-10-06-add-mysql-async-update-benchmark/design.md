# Design

## Context

原复杂方案未实施。用户明确要求简化后执行。本方案围绕现有 `prepare.mjs`、`run.mjs`、`collect.mjs` 和看板展开，不重新设计目录或数据系统。

## Goals / Non-Goals

**Goals:**
- 同批、同资源运行 1/1 同步与 2/0 异步索引更新。
- 核验实际参数，恢复原配置，保存可追溯结果并加入现有图表。

**Non-Goals:**
- 不实现独立数据库、逻辑快照、锁、持久恢复记录、环境指纹或历史报告选择。
- 不重新跑点查/读写混合，不测试断电或崩溃恢复，不保证异步必然更快。

## Decisions

### 1. 复用三个现有脚本

新增 `mysql:durability` 入口，按 `1/8/32` 并发串行运行同步、异步更新。每个组合先在 1/1 配置下调用现有准备脚本重建 `sbtest`，再设置目标参数，调用现有运行脚本；结束时恢复进入测试前的原值。

prepare 增加可选清单文件名前缀，run 增加可选环境清单路径和负载容器名称，collect 增加对照模式。原默认参数行为不变，不增加数据准备抽象或通用调度系统。

配置：

| 场景 | innodb_flush_log_at_trx_commit | sync_binlog | innodb_flush_log_at_timeout |
| --- | --- | --- | --- |
| update_index | 1 | 1 | 1 |
| update_index_async | 2 | 0 | 1 |

两组均核验 `log_bin=ON`，复用相同 `oltp_update_index.lua`，保持表数、行数、索引、随机分布、种子、资源和工具版本。重新生成数据只保证相同 recipe 与规模，不声称逻辑字节、物理布局或缓存状态完全一致。

### 2. 少量必要保护

只使用本项目 Compose MySQL 服务，核验项目/服务标签和原始 1/1 配置，不操作任意远程实例。binlog 未开启时中止；不关闭日志、不使用 `SET PERSIST`。

每组切换后和运行后回读日志参数。使用 `try/finally` 恢复原值并核验；捕获 SIGINT/SIGTERM，停止本次命名负载容器后恢复。恢复失败则返回失败且不更新看板。

无并发锁，文档要求测试期间不运行其他基准。SIGKILL/VM 故障不承诺自动恢复；文档给出手动检查或重启项目 MySQL 的办法。

### 3. 文件名隔离，不做复杂批次系统

沿用原目录，用自动生成的唯一 `runGroup` 作为原始文件、准备清单及汇总的文件名前缀，覆盖前拒绝冲突。

每次运行继续携带完整环境快照，只补充实际 `logBinEnabled`、`flushLogAtTimeout`。每组合环境有自己的路径，不能把第一组同步值用于异步结果。

对照汇总只读取指定 runGroup 的两种更新场景，调用原统计算法。汇总增加实际环境和测试日期到每条 series/组合，不增加 profile/environment/dataset 的 ID 注册表。

旧原始文件和默认标准化/汇总保留。发布前将现有页面 JSON 保存一份带前缀的文件作为追溯资料，不做历史选择界面；新页面保留历史点查/混合曲线，以新同步组替换当前更新曲线，再增加异步曲线。跨批次日期在明细中说明，不把历史数据当正式日志策略对照。

### 4. 看板只做增量修改

增加第四场景颜色，控件按现有报告生成，旧三场景报告仍可显示。场景明细和环境区显示各组实际 redo、binlog、刷盘周期及测量日期。

保持现有四指标、筛选、刻度与并发联动。不新增独立比值区。异步风险与跨批次背景参照明确标注。

### 5. 测量与测试

六组合，每组合预热 60 秒、两次测量各 120 秒，TPS/p99 差异超过 10% 补第三次。两次均值、三次中位数与稳定性计算保持原样。

先做单测与短运行核验参数/恢复/结果文件，再跑完整对照并发布。新入口的 dry run 只打印计划，不启动容器或写文件。

## Risks / Trade-offs

- [降低持久化保障] → 保留风险标签，只用于本地测试。
- [没有锁与持久恢复状态] → 不并行测试；可捕获中断自动恢复，强制终止后手动检查。
- [生成数据与系统状态存在波动] → 保持 recipe、资源与协议，保留重复结果和稳定性，不声称完全受控。
- [两个日志参数同时改变] → 只讨论联合影响，不分摊各自贡献。

## Migration Plan

原 MVP 默认流程不变。验证新入口后执行六组合，确认恢复成功再更新看板。旧结果继续留在原目录与 Git 中，无数据库迁移。
