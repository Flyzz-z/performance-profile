# Proposal

## Why

当前 MySQL 报告依靠纵向大图和独立读写比值卡片组织结果，比较时需要频繁滚动；环境信息不完整，移动端图表依赖横向滚动。需要将页面优化为可直接比较三类场景的性能看板，并清晰交代每项结果的环境与资源边界。

## What Changes

- 将详情页重组为紧凑的报告标题、资源与协议摘要、统一性能看板、结果明细和环境明细。
- 移除独立“读写差异”区域和比值卡片，通过相同坐标轴、场景颜色及同并发数值体现读、写、混合场景差异。
- QPS、TPS、p95、p99 分别使用独立面板，支持场景筛选、线性/对数刻度切换，以及鼠标、触摸和键盘查看数值。
- 明确展示 MySQL 容器 CPU 与内存上限、Buffer Pool、连接上限、事务隔离及已记录的持久化参数；压测端、Docker VM 和宿主机资源分别展示。
- 改进坐标轴单位、有效数字、零值与缺失值处理、稳定性状态、结果追溯，以及加载、空数据和异常状态。
- 更新索引页为与详情页一致的紧凑结果入口，不再把写读比值作为独立摘要指标。
- 只复用现有测试结果，保持压测参数、汇总算法、原始结果和数据格式不变，不重新运行 MySQL 测试。

## Capabilities

### New Capabilities

- `mysql-results-dashboard`: 定义 MySQL 结果界面的布局、指标交互、完整环境展示、响应式行为和数据状态，不涉及性能测试执行。

### Modified Capabilities

无。当前主规格目录为空；`add-mysql-benchmark-mvp` 已实现但尚未归档，其中 `mysql-performance-benchmark` 定义测试与结果契约。本能力补充其界面要求，不重新定义测试行为，不删除已有读写对比数据。

## Impact

- 主要修改 `site/mysql.html`、`site/index.html`、`site/styles.css`、`site/app.js`，按需要增加本地展示辅助模块、界面测试和使用文档。
- 现有 `site/data/mysql.json` 继续作为页面事实来源；只读使用原始结果入口和报告中的历史环境快照。
- 不修改 `benchmarks/mysql/compose.yaml`、压测脚本、原始结果和标准化/汇总文件，不引入后端、实时监控或公网部署。
- 本 change 以前一个 MVP 的当前实现为前置，不自动归档或改写旧 change。
