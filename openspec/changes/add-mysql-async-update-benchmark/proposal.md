# Proposal

## Why

增加一个异步刷盘索引更新场景，直观比较降低提交持久化保障后的吞吐与延迟。按照用户确认的简化方案，复用现有流程，不建设通用实验管理系统。

## What Changes

- 新增 `update_index_async`，同一更新 SQL 使用 redo=2、sync_binlog=0；同批重测 `update_index` 的 1/1 同步对照。
- 保持日志开启，运行前后核验实际参数，正常结束、错误和可捕获中断后恢复原值；不永久修改 `my.cnf`。
- 保持原并发 `1/8/32`、60 秒预热、两次 120 秒及超阈值补第三次的协议。
- 复用原数据准备，每个组合重建同规模、相同种子的数据；原 `sbtest` 会重建，不保存数据库状态或逻辑快照。
- 原始结果、环境和汇总使用唯一文件名前缀，不覆盖历史结果；看板增加第四场景并显示各场景日志参数和日期。
- 删除原复杂方案中的专用数据库、数据快照、排他锁、持久恢复记录、环境指纹与历史报告选择。

## Capabilities

### New Capabilities

- `mysql-durability-comparison`: 轻量同步/异步索引更新对照、参数恢复、结果保存与看板展示。

### Modified Capabilities

无，既有能力尚未归档为主规格，原 MVP 默认命令和三场景保持兼容。

## Impact

修改现有准备、运行、汇总脚本的少量参数接口，新增一个成对入口和必要测试。修改现有看板与文档，复用统计与图表。没有新运行时依赖、数据库管理框架或后台服务。
