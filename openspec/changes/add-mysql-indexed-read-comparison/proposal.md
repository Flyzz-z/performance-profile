## Why

现有主键点查使用主键索引，无二级索引更新也仍按主键定位，缺少相同查询在有二级索引与无可用索引时的性能对照。补充独立正式实验，量化二级索引等值查询与全表扫描的吞吐、延迟和资源差异。

## What Changes

- 新增独立索引读实验：两组相同逻辑数据、相同 `SELECT c FROM 表 WHERE k=?`，仅改变 `k` 二级索引是否存在；保留 `id` 主键，每次查询恰好返回一行。
- 每组 10 表 × 100,000 行；MySQL 8 CPU / 6 GiB、Buffer Pool 3 GiB，sysbench 4 CPU / 1 GiB，沿用 ARM64 及正式报告的软件与镜像。
- 两组各测 1/8/16 并发，共六组合；预热 30 秒，两次 90 秒测量，吞吐或 p99 差异超过 30% 补第三次。净测量 21–30 分钟，准备及验收另计。
- 保存执行计划、数据一致性、SQL 与脚本身份、全部观测、两端资源采样和恢复证据；独立完整验收后原子发布。
- 经用户确认，将容器健康检查改为 mysqld 进程/socket 检查，避免周期性健康检查连接干扰负载隔离巡检；启动入口继续用 SQL 核验可用性。
- MySQL 页面将两组加入统一性能看板，展示 QPS/TPS、p95/p99、同并发吞吐倍数、CPU、稳定性和原始资料；支持作者手写结论。
- 开发验证数据独立存放；新实验拥有自己的日期和环境，不改写既有六场景、32 并发补测、缓存及热点实验，也不参与索引页既有峰值。

## Capabilities

### New Capabilities
- `mysql-index-read-comparison`：独立索引查询与全表扫描实验的数据、测量、证据、恢复及正式发布契约。

### Modified Capabilities
- `mysql-results-dashboard`：将索引读对照加入统一看板的图表、同并发比较、原始记录及手写结论。

## Impact

- 新增 MySQL 读查询 Lua 负载、独立编排及验收发布模块，复用现有日志恢复、重复测量、解析和资源采样工具。
- 增加 `mysql:index-read` 命令及实验文档；使用专属数据库，避免现有通用准备入口重置 `sbtest`。
- 报告新增可选 `indexReadExperiment` 字段；修改 `site/mysql.html`、`site/app.js`、必要样式与报告投影，增加 `conclusions.json` 的 `index-read` 空位。
- 增加针对数据/执行计划不符、重复及采样不足、恢复失败和发布隔离的验证；复用现有原始资料路由，无新外部依赖。
