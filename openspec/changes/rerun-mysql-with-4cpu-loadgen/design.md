# Design

## Context

用户已明确要求按确认方案直接实施。复用已有prepare/run/collect与日志恢复入口；当前发布会合并历史点查/混合，必须改为整轮正式数据替换。主规格目录仍为空，前几个change不自动归档。

## Goals / Non-Goals

**Goals:** 固定4 CPU压测端，重测四场景12组合，采集两端资源证据，最终仅发布该轮正式数据。

**Non-Goals:** 不新增场景/并发、1CPU/4CPU对照图、监控平台、锁或恢复框架；不保证加CPU消除拐点，不无证据断言根因。

## Decisions

### 1. 扩展现有入口，不另建调度系统

新增 `mysql:formal` 指向已有入口的正式模式，保留日志策略专用入口用于单独开发资料。正式模式场景为 point_select/update_index/update_index_async/read_write，各1/8/32，统一结果组。

除异步更新2/0外均采用1/1，binlog ON、timeout=1。每组仍调用prepare重建同规模数据，恢复与错误处理沿用原逻辑。

实际负载容器4 CPU/1 GiB须回读核验。短参数或子集自动标为verification，不能发布。

### 2. 轻量资源采样

正式测量通过本地Docker socket只读Stats API，每5秒采样MySQL与本次命名sysbench容器，无远程服务、无新依赖。短内部验证可用1秒间隔，仅验证接口。

保存CPU累计使用、采样时间及限流累计计数。区间CPU百分比为CPU使用纳秒差/墙钟纳秒差×100；4CPU可达约400%，配额占比再除以4。汇总保存平均/最高CPU、配额占比、限流period差及限流时间差；限流时间可能跨CPU累计，不能转成墙钟百分比。

采样原始JSON位于该正式run的raw文件旁；至少覆盖80%测量时长且字段/配额有效。采样不足的正式运行不发布，不能用零替代未知值。只在正式测量采样，预热不计入资源结论。

发布时重新检查原始采样，连续采样间隔不得超过10秒，120秒测量的采样跨度不得超过130秒。宿主机或VM暂停形成的大跨度不能充当有效覆盖。

### 3. 明确正式发布门槛

元数据增加purpose=formal/verification；正式发布必须：单结果组、12完整组合、协议60/120/2/10%、4CPU真实环境、全部有效、每次资源采样有效、恢复成功。

collector为正式模式输出自身四场景数据，不读取旧报告补曲线。旧结果和验证仅存benchmarks开发/归档区域；site/data最终仅使用mysql.json。非正式collect不再覆盖最终看板，历史策略入口也不自动发布。

替换前在benchmarks summary保存原报告，并使用校验后临时文件替换。旧site/data备份移到归档目录，不增加历史选择界面。

2026-10-06用户授权补齐并发布：仅人工替换 `read_write c32` 完整组合。先核验其余11组合有效且环境一致，用哈希保护其记录；把受中断组合的全部输出、采样、元数据、环境与数据集清单按原相对路径完整隔离到本地 `results/verification/`，保存归档清单，不改写原始内容。随后复用现有prepare/run与日志恢复辅助函数，在原正式结果组内重建100万行，预热60秒、两次120秒、超过10%补第三次。实际环境重新回读，完整结果组仍须满足原发布门槛。该操作不增加通用恢复入口；普通子集运行仍为verification。补测期间使用macOS防闲置休眠保护，不能替代采样有效性校验。

### 4. 辅助证据与结论

沿用四指标看板，环境显示sysbench 4 CPU，逐次结果保留资源JSON链接。所选并发可显示两端CPU配额占比与限流计数，作为该次正式运行的辅助数据，不增加性能场景。

最终报告仍只发布同轮正式数据。页面不展示异步持久化风险横幅、历史背景参照或批次拼接说明；风险保留在实验README，不因旧JSON中存在risk/note/sourceRole字段而重新渲染。保留场景名称、实际日志参数、测量日期、稳定性与本机虚拟化限制。移除文案不改变数据来源，不将旧报告声称为本轮正式结果。点查32若仍下降，只报告证据支持的CPU/限流现象；没有其他等待/IO证据不声称定位到MySQL内部函数。

## Risks / Trade-offs

- [资源采样增加轻微开销] → 本地只读API、5秒间隔、全部正式测量一致，不引入采样服务。
- [旧/短结果误发布] → 显式purpose与完整矩阵门槛，失败时保留当前可用报告。
- [4CPU仍受VM与MySQL配额约束] → 记录两端使用与限流，避免容量上限或必然提速承诺。
- [耗时较长] → 12组合基础测量60分钟，补跑最多24分钟，额外数据准备另计。

## Migration Plan

先完成接口与隔离测试，内部验证只留开发资料；确认资源采样与恢复有效后执行全轮。成功后整份替换最终报告并归档旧JSON，保留日志原值、旧原始数据及Git追溯，不删除数据库卷。
